answer
The question doesn't name a product, so here is the answer for each product that has 403 guidance in the knowledge base.

**Nimbus Relay** (first check) [1]
The token's scope includes the route being called. Scopes are per route since Relay 4.0; a token minted for `/orders` cannot call `/customers`.

Full checklist, in order [1]:
1. The token's scope includes the route being called.
2. The caller's IP is on the workspace allowlist, if one is configured.
3. The seat that owns the token is not suspended.

**Nimbus Pulse** (first check) [3]
The user who owns the API key is a member of the workspace the project belongs to.

Full checklist, in order [3]:
1. The user who owns the API key is a member of the workspace the project belongs to.
2. The API key is bound to the project being queried; keys are per project since 4.0.

**Nimbus Vault and Nimbus Ledger:** the knowledge base has no 403 troubleshooting for these products.
