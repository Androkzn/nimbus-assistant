Q4
A client is getting a 403 on the API. What should they check first?✓ PASS
1349 ms · $0.00052
answer
For **Nimbus Relay**:
1. Check first: The token's scope includes the route being called; scopes are per route since Relay 4.0 [1].
2. The caller's IP is on the workspace allowlist, if one is configured [1].
3. The seat that owns the token is not suspended [1].

For **Nimbus Pulse**:
1. Check first: The user who owns the API key is a member of the workspace the project belongs to [3].
2. The API key is bound to the project being queried; keys are per project since 4.0 [3].

For **Nimbus Vault** and **Nimbus Ledger**, I couldn't find this in the NimbusStack knowledge base. The knowledge base does cover troubleshooting procedures for Relay and Pulse.

Which of our products support SSO via SAML 2.0?✓ PASS
1312 ms · $0.00074
answer
The following products support SAML 2.0:

*   **Nimbus Relay**: Supported on the Enterprise tier [1, 5].

⚠️ **Documents disagree**: Regarding Nimbus Vault, the security overview (updated 2026-01-15) lists SAML 2.0 on Enterprise only [5], whereas the product document (updated 2026-07-03) and release notes (2026-04-14) state it is available on both Pro and Enterprise [2, 8].
